# Postmortem: GitHub Pages live site (2026-10-15)

## Request
Put the app on GitHub Pages as a portfolio piece, with a separate live branch, publishing blocked and a
banner explaining that the AI and publishing don't work there. The user also asked what else to block and
whether the approach was right.

## Advice given
- A static site can't be damaged by visitors: there's no server, and on a static host publishing would only
  save into the visitor's own browser. Blocking is for honesty, not safety.
- A separately edited live branch drifts from main. Agreed instead: one codebase with a build-time switch,
  and a `live` branch that only triggers deploys. The user also chose to keep the Describe box in keyword mode.

## What changed
- `lib/site.ts`: `LIVE_SITE`, `BASE_PATH`/`withBase`, `patternHref`, the repo URL and the publish-off message.
- `next.config.ts`: static export, basePath, trailingSlash and unoptimized images, only when live.
- `scripts/build-live.mjs` (`npm run build:live`): parks `app/api` in a `_`-prefixed (private) folder during
  the build, always restores it, and writes `out/.nojekyll`.
- Pattern pages moved from `/pattern/[id]` to `/pattern?id=` (static export doesn't allow on-demand dynamic params).
- Live behaviour: `LiveBanner` (sets `--banner-h` so the full-height editors still fit), "Live preview" header
  badge, disabled Publish buttons (with tooltip on a wrapper) plus a guard in `publishPattern`, keyword-mode
  Describe (no fetch, no "Try again"), no AI status polling, library = seeds only, feedback buttons hidden.
- Raw `history.replaceState` paths use `withBase`.
- `.github/workflows/deploy-pages.yml`: on push to `live` (or by hand): npm ci, lint, `build:live`, then
  upload and deploy to Pages. Actions are pinned to commit SHAs after semgrep flagged mutable tags.
- `docs/live-site.md`: how it works, how to update the site, one-time GitHub setup.

## Issues hit
- Deleting `app/pattern/[id]` with `git rm` removed the now-empty folder, so the first write of the new page
  failed; recreated the folder.
- A stale `.next/types` file referenced the deleted route; cleared it.
- lucide-react 1.x has no brand icons (no GitHub logo); used a generic code icon.
- Remembering a closed banner in sessionStorage during first render would mismatch the prerendered HTML;
  dropped it. Closing lasts until the next full page load.

## Verification
- `npm run build:live`: 6 static routes, `app/api` restored afterwards.
- Served `out/` under `/BraceletAI/` and tested in a headless browser: banner and badge, Publish disabled in both
  editors, keyword-mode Describe in both, library (93 patterns), pattern pages, PNG export, remix, deep links
  on reload. No `/api` requests, nothing outside the base path, no console errors or failed requests.
- Normal build and local dev unchanged: AI status, publishing (redirects to `/pattern?id=`), feedback.
- lint and tsc clean; semgrep clean after pinning actions.
